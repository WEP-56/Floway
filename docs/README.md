# FLVPcore 内核接入设计

调研日期：2026-10-30（Asia/Shanghai）。本目录中的调研和架构文档定义长期实施基线。项目已开始 M0.1 普通代理原型开发；**这些设计文档中的全部功能并不都已实现，TUN / VPN 尚未接入**。已实现能力、构建方法和实测范围以 [M0.1 实施记录](m0-implementation.md) 为准。

当前只交付 Windows 与 Android；其他平台仅保留共享模型和接口扩展点，待双端稳定、功能完善后再实施。

## 文档用语

| 标记 | 含义 |
| --- | --- |
| 已核实 | 当前固定提交的源码或本轮测试可以支持此结论 |
| 设计约定 | FLVPcore 决定采用的客户端契约，尚待实现 |
| 需补齐 | 上游当前接口不能满足，需要补丁或自建宿主 |
| 待实测 | 源码不足以证明，需真机或系统集成测试 |

文中的 `CoreBridge`、`CoreHost`、`CapabilityManifest`、配置事务字段等均为 FLVPcore 的**设计接口**。真实上游 API 和 C ABI 单独列出，不能把设计名称直接当作已有接口调用。

## 建议先完成的工作

1. 固定 vp_core 提交与自维护补丁，完成无 TUN 的配置编译、普通代理和通信原型。
2. Windows 补齐精确路由管理、受限提权宿主和退出清理；Android 补齐 protect、TUN/DNS、FD 所有权及就绪回执。
3. 双端共用配置与规则测试语料，通过断网恢复、长稳、升级回滚后，再把设计资产中的对应功能接到真实能力上。

`UI-design-pages` 只提供视觉和交互参考。例如其中的“网络栈选择”“修改后自动重载”必须受能力与变更分类约束，不能直接沿用为内核功能承诺。
